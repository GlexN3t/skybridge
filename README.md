# SkyBridge — ESP32 MAVLink Telemetry Bridge

A lightweight companion-computer platform for drones: an ESP32 joins the
vehicle's WiFi link, speaks [MAVLink v2](https://mavlink.io) (the protocol
used by ArduPilot and PX4 autopilots), and exposes live telemetry
(attitude, position, battery) over an on-board web dashboard.

```
┌──────────────────┐   WiFi/UDP    ┌───────────────┐   USB/UART   ┌────────────┐
│  ArduPilot SITL  │◄─────────────►│    ESP32      │◄────────────►│  Flight    │
│  (or real GCS)   │   MAVLink v2  │  (SkyBridge)  │   MAVLink    │ controller │
└──────────────────┘               └───────┬───────┘              └────────────┘
                                           │ WebSocket
                                           ▼
                                   Live telemetry page
                                   (served from the ESP32)
```

## Why hand-rolled MAVLink?

Off-the-shelf MAVLink libraries (pymavlink, the C headers generated by
`mavgen`) are black boxes. SkyBridge implements the v2 wire format from
the protocol spec — framing state machine, CRC-16/X-25 with per-message
`CRC_EXTRA` magic bytes, zero-copy byte-at-a-time ingestion — as ~200
lines of auditable C, unit-tested on the host and re-verified on-target
at every boot.

## Repo layout

| Path | What it is |
|---|---|
| `firmware/` | ESP-IDF 5.x project (target: ESP32-WROOM-32 devkit) |
| `firmware/main/mavlink_parse.c` | MAVLink v2 framing parser + builder |
| `firmware/main/mavlink_decode.c` | Typed payload decoders (shared firmware/host) |
| `tools/test_mavlink_parse.c` | Host-side unit tests (plain gcc, no toolchain needed) |
| `tools/virtual_drone.py` | MAVLink v2 quadcopter simulator — hardware-free dev |
| `tools/bridge_sim.c` | The firmware data path compiled for the host (UDP) |
| `tools/mavlink_decode.py` | Python mirror of the firmware decoders |
| `tools/ground_station.py` + `.html` | Browser ground station: SSE feed + canvas HUD |
| `tools/test_integration.sh` | End-to-end interop test: Python drone ↔ C bridge |
| `docs/` | Architecture, research notes, decision log |

## Quickstart

Run the protocol tests right now (any machine with gcc + python3, zero
dependencies):

```sh
gcc -Wall -Wextra -Werror -O2 -I firmware/main \
    tools/test_mavlink_parse.c firmware/main/mavlink_parse.c \
    firmware/main/mavlink_decode.c \
    -o build/test_mavlink_parse && ./build/test_mavlink_parse
```

Watch a simulated drone fly (end-to-end telemetry over UDP, MAVLink v2
on the wire):

```sh
./tools/test_integration.sh
```

**Open the ground station GUI** — a live artificial-horizon HUD in your
browser, served by pure-stdlib Python (no frameworks, no network
beyond loopback):

```sh
python3 tools/virtual_drone.py --port 14550 &     # simulated quadcopter
python3 tools/ground_station.py                   # http://127.0.0.1:8080
```

Sample output — a sinusoidal banking turn, dead-reckoned GPS, draining
battery, all decoded by the same parser that ships on the ESP32:

```
SYS_STATUS   battery=12.59 current=4200 remaining=100
ATTITUDE     roll=  +9.05 pitch=  +6.53 yaw=   5.79
POSITION     lat=47.3977871 lon=8.5456007 rel_alt=50.0
```

Build the firmware (requires the ESP-IDF toolchain — see
`tools/setup-toolchain.sh`):

```sh
cd firmware && idf.py build flash monitor
```
